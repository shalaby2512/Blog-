Building the software backbone of an autonomous follow-cart.

I’m Mohammed Shalaby, the ROS 2 architecture and systems-integration lead for Trolley-X. My work examines how a modular ROS 2 Jazzy architecture can connect sensing, decision-making and embedded motor control reliably on a low-cost physical platform.

Research focus

From working prototype to defensible research

Primary research question

How can a modular ROS 2 Jazzy architecture improve the reliability, responsiveness and maintainability of a low-cost autonomous follow-cart when integrating high-level navigation with embedded motor control?

01

Communication reliability

Measure command latency, jitter, message loss and recovery across the ROS 2–microcontroller boundary under realistic operating loads.

02

Safe system behaviour

Design and test a state machine that makes transitions between idle, following, obstacle stop, fault and recovery explicit and repeatable.

03

Reproducible integration

Evaluate whether clear interfaces, lifecycle management and structured logging reduce integration faults and improve test repeatability.

Scope note: These are the questions and metrics guiding the study. Results will be reported only after experiments are completed.

Own the migration of the project software to the physical ROS 2 Jazzy stack, including packages, launch structure, parameters and interface contracts.

Motor-control interface

Develop the bidirectional Arduino interface for velocity commands, feedback, watchdog behaviour and safe handling of lost communication.

System state machine

Define deterministic operating states and guarded transitions so faults, emergency stops and recovery can be tested systematically.

Software integration

Integrate team subsystems through documented topics, services, coordinate frames and data contracts, with version-controlled releases.

Return-to-home study

Investigate an optional Nav2-based recovery path that can return the cart to a known location when following ends or a task is cancelled.

Verification & evidence

Create repeatable scenarios, logs and quantitative comparisons that connect architectural decisions to observable system performance.
